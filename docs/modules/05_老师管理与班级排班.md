# 05 · 老师管理与班级排班（成员 5）

## 1. 一句话职责

管老师档案、外加一条“给班级分老师”的排班关系。
本轮新规则：一位老师同一时间只能负责一个班级，班主任和授课老师不能同人。

文件：`model/teacher.py`、`model/class_teacher_relation.py`、
`scheme/teacher.py`、`scheme/class_teacher.py`、
`dao/teacher_dao.py`、`dao/class_teacher_dao.py`、
`api/teacher_api.py`、`api/class_teacher_api.py`，
测试 `tests/test_teachers.py`（25 条）、`tests/test_class_teachers.py`（28 条）。

## 2. 接口一览

老师：POST / GET 列表 / GET 详情 / PATCH / DELETE（共 5）。
排班：PUT `/classes/{cid}/teachers/{tid}` 建关系、
GET `/classes/{cid}/teachers` 查班级老师、
DELETE `/classes/{cid}/teachers/{tid}`（可带 `relation_type`）解关系。
前端再补：GET `/class-teacher-relations` 全局排班大表（筛选+分页）、
GET `/teachers/{id}` 详情附 `relations`。

## 3. 请求体逐字段

TeacherCreate：必填 `teacher_no`（全表唯一）、`name`；
`teaching_years` 默认 0（≥0，可小数）；`teacher_status`（在职/离职，
默认在职）；`gender/specialty/phone/contact_info` 可空。
电话只放 `phone`，微信邮箱放 `contact_info`，两个字段不混存。
ClassTeacherRelationCreate：只传 `relation_type`（班主任/授课老师，
默认授课老师），班和老师的 ID 在路径里。

## 4. 排班 PUT 的处理步骤（重点背）

1. 班、老师存在且未删除（404）。
2. 班级已结课？已结课拒绝新增（409）。
3. 完全相同的有效关系已存在？直接返回它，PUT 幂等不重复插。
4. **铁律 1**：查老师占用（`get_teacher_busy_relation`）：
   在未结课班级上有任何有效关系就算忙。忙在别的班 →
   409「该老师已负责未结课班级 XXX」。
5. **铁律 2**：忙在同一个班但角色不同 →
   409「班主任和授课老师不能是同一人」。
6. **铁律 3**：角色是班主任时查本班班主任（`get_class_active_head`），
   有 → 409「该班级已有班主任」。
7. 全过才插入新行。旧的已解除关系不动，作为历史留底。

## 5. 业务规则和边界

- 在职/授课状态：前端还有 `teaching_status`（可授课/暂停授课）；
  离职或暂停授课不许新分配（TS 层 409，Python 侧用 teacher_status 判断）。
- 一个班的班主任只有一位，但授课老师可以多位——多位授课老师的意思是
  各自负责不同科目，每个人也都只占这一个班。
- 换班先解旧：解了旧关系才能绑新班；班级结课后占用自动解除，
  老师可去新班，历史行保留展示。
- 删除老师先要解完关系（409）；被历史快照引用的关系也只逻辑删除。
- 班级 PATCH 重新开班时闸门最严：名下每位老师都必须现在空闲。

## 6. 测试清单（28 条重点）

正常：建关系（班主任/默认授课老师）、两人加进同班各一条、
列表带老师信息、单删一人不影响他人、解后重建是新 id。
铁律：同人兼任 409、老师跨班 409、授课老师跨班也不行 409、
一班双班主任 409、解绑后可绑新班、结课后可去新班、
结课班级新建排班 409、角色非法 422、班/师不存在 404。
删除：有关系删班 409、删师 409、解完都能删。

## 7. 答辩话术

60 秒介绍：
> 我负责老师档案和班级排班，老师 5 个接口、排班 3 个接口。
> 新版排班三条铁律：一位老师同一时间只负责一个未结课班级；
> 班主任和授课老师必须是两个人；每班最多一位班主任。
> 实现上是接口层用简单 if/else 依次拦：查存在、查结课、查幂等、
> 查占用、查角色同人、查已有班主任。已结课的历史关系保留展示
> 但不占用老师。用 28 条测试把规则全锁住，重点是“一人一班”和换班路径。

预判提问 1：“同一个老师当两个班授课，为什么不许？”
> 本轮业务定下来的：一人一班是为了排课口径明确，避免同一人出现
> 在两张排班表里排查不清。如果以后允许多带班，只要放宽占用检查这一条即可，
> 数据结构不用改。

预判提问 2：“怎么防止并发把一位老师分到两个班？”
> Python 层是先查后写的高并发下理论上可能竞速，这点我答辩时会直接承认：
> 基础版用业务检查；TS 实现里用了老师行锁串行化。
> 真要再加保险，可以给有效关系加列唯一索引，但要兼容逻辑删除重建，所以现阶段没上。

预判提问 3：“已结课的班还在排班表里是不是 Bug？”
> 不是。是历史排班，照样展示但明确不占用老师：
> 老师因此能去新班。筛“当前排班”按班级状态排掉已结课即可。
