# 07 · 公共规范与系统集成（成员 7）

## 1. 一句话职责

定下全项目公用的规矩，再把 6 个业务模块拼成能跑的系统：
统一响应、错误格式、逻辑删除、分页、路由注册、集成测试。

文件：`backend/database.py`、`backend/api/common.py`、
`backend/dao/common.py`（分页两函数）、`backend/scheme/common.py`、
`backend/main.py`、前端 `src/components/Shell.tsx`、`src/lib/*-api.ts`
（预览代理层）、测试目录 `tests/`。

## 2. 公共约定清单

- 成功 `{"code":0,"message":"success","data":...}`；列表
  `{"items","total","page","page_size"}`；删除 204 无体。
- 业务码 = HTTP 状态码 × 100 + 1：40001/40401/40901/42201/50001。
- 分页 `page≥1`、`page_size` 默认 20、上限 100，全走 `dao/common.paginate`。
- 逻辑删除 `is_deleted/deleted_at`；普通查询默认过滤；
  子记录还要看所属学生未删。
- PATCH `exclude_unset=True`；必填不能 null（`check_not_null`）。
- PATCH 一系列时用最终值复检（日期先后、薪资周期配对、排班占用）。
- 金额 `Decimal`，JSON 输出为字符串 "15000.00"，杜绝浮点误差。

## 3. 主要接口面（集成层负责）

| 块 | 路径 | 职责 |
|---|---|---|
| 异常处理 | `main.py` 的 4 个 handler | HTTP/校验/约束/未知错误统一格式 |
| 健康检查 | GET `/api/v1/health` | 返回 `{status: "ok"}` |
| 路由注册 | `main.py` include_router | 8 个业务模块统一 `/api/v1` |
| 预览代理 | `app/api/v1/[...slug]` | 配 `WOLIN_API_URL` 时只代理 FastAPI，不回退 |
| 演示初始化 | `src/lib/bootstrap.ts` | 建表 + 幂等修历史 + 种子数据（修表结构） |
| 全局排班表 | GET `/api/v1/class-teacher-relations` | 分页融合 class+teacher DTO |

## 4. 排班全局表怎么做的

`relationRows` 三表 JOIN（关系+班级+老师），一次拿回班级、老师、角色；
筛选用 `class_id/teacher_id/relation_type`，`ORDER BY class_id, id` 后内存分页
（基础版数据量小；对外接口返回 PageData 结构和后端一致）。
班级 overview 更是聚合了五类信息：人数、性别、及格率/平均分（只取有效成绩）、
达标人数子查询、已就业去重人数——都能被班级详情页整段展示。

## 5. 历史张量修复（平台初始化）

`prepareDatabase` 每次启动依次做：建表（含新增字段补列）→
补空的 `class_no_snapshot`（从学生当前班级写入）→
同一老师在未结课班级多条有效关系时只留最早一条其余逻辑删除 →
快照列 SET NOT NULL → 空库才写演示种子。
每一步都是条件重复执行不报错（幂等），不会重复产生数据。

## 6. 排班铁律怎么落地两层

| 层 | 校验 | 返回 |
|---|---|---|
| 前端禁用 | 老师状态/占用读 relations 判掉 | 选项不可选 |
| 后端校验 | locked 老师行 + findBusyRelation 查占用 | 409 明确提示 |

并发时 Python 业务检查可能竞速，这点在成員 5 文档里也写了承认路径和升级方案；
TS 侧以老师行锁串行确保不分身。

## 7. 最终验收动作（每个人都要过）

1. Python：`python -m py_compile backend/*.py backend/**/*.py`。
2. FastAPI 测试：`WOLIN_TEST_DB_URL=mysql... pytest tests -v`（专用测试库！）。
3. 前端：`npx next typegen`、`tsc --noEmit`、`npm run build`、`build_and_start`。
4. 手点四条主流程：新增学生查详情、按学生+序次改分、大表导 Excel、
   新增就业（Offer 早于/无开放两失败）、班级删不掉、排班三条铁律各试一次。

## 8. 答辩话术

60 秒介绍：
> 我负责公共规范和集成。统一了响应外壳、错误码、分页、逻辑删除和时间口径，
> 每个模块只按这一套规矩填业务。最近两轮专项：一个是把各 DAO 分页抽成
> clean_text + paginate 两个公共函数；一个是给就业日期和排班加硬校验，
> 前提/后置在前后端双拦。集成层还负责把历史脏数据在启动时幂等修复好：
> 快照回填、重复排班清到只留一条。

预判提问 1：“分页为什么抽公共函数，两行代码有必要？”
> 六个模块一个样写了不下 6 遍，长的版本还各自不同。
> 抽出来一次改对所有地方都对（比如空字符串过滤和总数位置）。
> 函数体只有两行，但一致性值得。

预判提问 2：“前端有一套、后端有一套，不就重复了吗？”
> 契约同一套：路径、字段、响应、错误码和规则都一致。
> FastAPI 是业务后端，预览代理是同一套接口的落地实现。
> 对接真实环境时配 `WOLIN_API_URL` 一条变量整套切换到 FastAPI 和 MySQL。

预判提问 3：“测试跑在 MySQL 还是别的？”
> 只认 MySQL。conftest 没设 `WOLIN_TEST_DB_URL` 就拒载，
> 并且不是 mysql 开头直接报错，防止误连正式库或其他数据库。
> 预览库不接后端测试，两条线不互相代替。

预判提问 4：“班级下有学生不能删除这条谁兜底？”
> 班级接口删除前查人数，409 拦住；前端班级列表不禁用按钮，
> 靠后端这道闸。成员 4 文档里有完整表述，我这边对此专门维护了回归用例。
