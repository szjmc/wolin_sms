# 02 · 考核成绩管理（成员 2）

## 1. 一句话职责

管成绩的录入、查、改、删。铁律一条：查改删一律按「学生 + 第几次考试」定位，
绝不用成绩表的自增 id——老师手里只有「张三第 2 次考核」，没有成绩 id。

文件：`model/score.py`、`scheme/score.py`、`dao/score_dao.py`、
`api/score_api.py`，测试 `tests/test_scores.py`（24 条）。

## 2. 接口一览（5 个后端 + 4 个全员大表接口）

后端业务接口：

| 方法与路径 | 作用 |
|---|---|
| POST `/api/v1/scores` | 新增成绩（student_id + exam_no + score） |
| GET `/api/v1/students/{id}/scores` | 学生成绩列表（可按 exam_no 过滤） |
| GET `/api/v1/students/{id}/scores/{exam_no}` | 按学生+序次查一条 |
| PATCH `/api/v1/students/{id}/scores/{exam_no}` | 按学生+序次改分数 |
| DELETE `/api/v1/students/{id}/scores/{exam_no}` | 按学生+序次逻辑删除 |

考核管理页专用（`src/lib/score-api.ts`，契约与 FastAPI 一致）：

| 接口 | 作用 |
|---|---|
| GET `/api/v1/scores` | 全员大表：姓名/学号、班级、序次、分数段、排序、多条件分页 |
| GET `/api/v1/scores/summary` | 总条数、平均分、≥60 条数、≥80 条数 |
| GET `/api/v1/scores/export` `/template` | 导出筛选结果 / 下载导入模板（真正 .xlsx） |
| POST `/api/v1/scores/import` | 导入：全行先校验，出错整批拒绝，错误指出第几行 |

## 3. 请求体逐字段

ScoreCreate：`student_id`（正整数，必填）、`exam_no`（≥1，必填）、
`score`（0–100，最多两位小数，必填）。
ScoreUpdate：只传 `score`——序次在路径里，改序次不认。
ScoreRead：`id`（只展示，前端别拿它发请求）、`student_id/exam_no/score/created_at/updated_at`。

## 4. 每个接口的处理步骤

**新增**：① 学生存在未删（404）→ ② 这学生这序次已有有效成绩？
（`get_active_score_by_exam`，409）→ ③ 入库返 201。

**查一条**：先查学生（404），再按学生+序次查有效成绩，没记录 404。

**改分数**：查到成绩 → 只改 `score` 一个字段，其他不动。
前端大表行「改分」现在弹出模态窗（学生信息只读、分数可编），
保存即调这个 PATCH，不跳页面。

**删除**：查到成绩 → 打删除标记。删后同一序次可以重录
（普通查询只看未删除的），历史行还在库里。

## 5. 业务规则和边界

- 同一学生同一序次最多一条有效成绩；删后可重录；两人同时录入冲突返回 409。
- 学生被删后回不来：列表 404、详情 404、给这个学生加成绩也 404。
- 分数 0 和 100 都合法；超范围 422；序次 0 是非法的。
- 评级：≥80 优秀、60–79.99 及格、<60 不及格，前后端说法一致。
- Excel 导入：表头认「学号/考试序次/分数」，公式单元格、空值、超范围都算错；
  1000 行/5MB 上限；已有成绩不覆盖，提示用改分功能；发布时整批事务。

## 6. 测试清单（24 条，挑重点记）

正常：录入返回 "88.50" 形式、0 分和 100 分都过、列表按序次排、按序次过滤。
异常：101/-1/序次 0 都是 422、学生不存在 404、重复录入 409。
定位：用学生+序次能查到；拿成绩 id 当序次用大多 404（证明不按 id 查）。
删除与重录：删除 204 → 再录同序次 201、列表只剩新一条。
可见性：学生删除后其成绩 404、不能给删了的学生加成绩。

## 7. 答辩话术

60 秒介绍：
> 我负责考核成绩，5 个后端接口加考核页的大表工具。
> 最核心的设计是按「学生 + 考核序次」定位成绩而不是按自增 id，
> 因为老师手里只有这个信息。防重就靠同一学生同一序次最多一条有效成绩，
> 删除后能重录，所以不用复杂的唯一索引，而是接口层先查后写，
> 并发冲突返回 409。测试 24 条，重点是用新接口做查、改、删、删后重录。

预判提问 1：“成绩 id 不是现成的吗，为什么不用？”
> id 是数据库自增的，老师录入时根本不知道。硬要按 id 操作，
> 就得先额外查一次 id、还要处理 id 被乱填的情况。
> 学生+序次本身就是业务上的唯一键，直接用它最贴近真实场景。

预判提问 2：“两个人同时给一个学生录同一次成绩怎么办？”
> 第一人成功，第二人查到已有记录返回 409，提示用修改。
> 导入 Excel 时也是整批校验，冲突行让导入整批失败，不会写一半。

预判提问 3：“删错一条成绩能恢复吗？”
> 逻辑删除，数据还在。只改 is_deleted 和 deleted_at，
> 同一序次可以重新录入一条新的，旧的历史还能查到。
