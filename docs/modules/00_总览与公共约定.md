> 成员 6 统计、成员 7 公共集成。本目录 01–07 每人一篇，对号入座。

## 1. 项目一句话

沃林学生管理系统（基础版）：管学生档案、考核成绩、就业记录、班级、老师，
以及基于这些数据的统计分析。后端 Python + FastAPI + SQLAlchemy + Pydantic v2，
数据库 MySQL 8.0；预览前端 Next.js 直连同一套接口约定。

## 2. 代码分层（请求走一遍）

```text
HTTP 请求
  → scheme   Pydantic 校验参数（类型、范围、日期先后），不合法直接 422
  → api      业务判断：记录是否存在(404)、编号是否重复(409)、规则是否满足(400)
  → dao      读写数据库（普通查询都带 is_deleted == 0）
  → model    ORM 对象 ⇄ 数据表
  → api      ORM 对象转成 XxxRead（顺手算出 age / annualized_salary）
  → 返回 {"code": 0, "message": "success", "data": ...}
```

| 目录 | 放什么 | 能写什么 | 不能写什么 |
|---|---|---|---|
| `backend/model/` | 一张表一个类 | 字段、类型、必填、注释 | 不写查询，不写 `__table_args__`（已全删） |
| `backend/scheme/` | `XxxCreate` / `XxxUpdate` / `XxxRead` | 字段校验、枚举、日期先后 | 不查数据库 |
| `backend/dao/` | 每个函数只做一件事的增删改查 | `get_by_id`、`list_`、`create_`、`update_`、`delete_` | 不做业务判断（比如“能不能删”归 api 层） |
| `backend/api/` | 一个模块一个路由文件 | 参数接收、`if/else` 业务判断、调 dao、组响应 | 不直接写 SQL |
| `backend/main.py` | 建表、CORS、异常处理、注册路由 | 全局行为 | 不写具体业务 |

## 3. 统一响应和错误（背下来）

成功：`{"code": 0, "message": "success", "data": ...}`。
分页的 `data` 固定是 `{"items": [...], "total": 总条数, "page": 页码, "page_size": 每页条数}`。
删除成功返回 `204`，没有响应体。

失败：`{"code": 业务码, "message": "人话说明", "details": []}`。
业务码 = HTTP 状态码 × 100 + 1：

| HTTP | 业务码 | 什么时候用 | 例子 |
|---|---|---|---|
| 400 | 40001 | 传参合法但违反业务规则 | 结课日期早于开班日期 |
| 404 | 40401 | 记录不存在、已逻辑删除 | 查不存在的学生、给已删学生录成绩 |
| 409 | 40901 | 编号重复、有关联数据挡着 | 学号重复、班级下有学生还想删班级 |
| 422 | 42201 | 参数类型/格式/范围错 | 分数 120 分、性别传“未知” |
| 500 | 50001 | 没料到的错误 | 统一记日志，不把堆栈给前端 |

状态码习惯：新增成功 201；查询/更新 200；PATCH 只传要改的字段；
`page` 默认 1，`page_size` 默认 20、最大 100。

## 4. 逻辑删除（全项目铁律）

- 所有业务表都有 `is_deleted`（0 未删 / 1 已删）、`deleted_at`、`created_at`、`updated_at`。
- DELETE 接口只打标记，不物理删除：`is_deleted = 1`，`deleted_at = 当前时间`。
- 普通查询和统计必须带 `is_deleted == 0`；成绩、经历、就业还要再看所属学生删没删。
- 主键一律 `BIGINT` 自增；业务编号（学号/班号/老师编号）全表唯一，
  已删除的编号也不能复用。

## 5. 三个最容易被问的计算口径

1. 年龄：只存 `birth_date`，返回时 `今年 - 出生年，生日没到再减 1`。
   “年龄 > N 岁”换算成 `birth_date <= 今天往前推 N+1 年`，直接比日期，不逐行算年龄。
2. 年薪等价值：`MONTH → 金额 × 12`，`YEAR → 金额本身`。只用于排序比较，
   响应里永远保留原始金额和周期。
3. 成绩达标：至少 1 条有效成绩，且所有有效成绩 ≥ 80。没成绩不算达标，
   有一条 79 分就不达标。不及格线是 60 分。
4. 结课后就业：学生 `training_graduation_date` 为空不能登记就业；
   `employment_open_date` 必须 ≥ 结课日期。
5. Offer 三态：`待处理 / 已接受 / 已拒绝`；接受一条其它自动拒绝；
   学生有"已接受"就是已就业，否则待就业（状态动态算，不落库）。
6. 登录权限：写操作必须带令牌；角色分工见 08 号文档的权限表。

## 6. 必填和选填的分界（2026-10 已全量复核）

原则：建档时必须知道的就 NOT NULL；可以后补的才允许为空。
容易混淆的一点：**PATCH 请求体里字段都是可选的**（不传表示不改），
但数据库必填字段一旦传了就不能传 `null`，由 `check_not_null` 拦截。

| 表 | 必填（NOT NULL） | 可空 | 备注 |
|---|---|---|---|
| classes | 班号、班名、开班日期、状态 | 结课日期 | 未结课当然没有结课日期 |
| teachers | 老师编号、姓名、教学年限、状态 | 性别、专长、电话、微信邮箱 | 先建档后补联系方式 |
| students | 学号、班级、姓名、出生日期、性别 | 籍贯、原院校、原专业、学历、培训日期、顾问编号 | 先建档后补档案 |
| scores | 学生、序次、分数 | 无 | 三个全必填 |
| past_experiences | 学生、工作年限 | 薪资、毕业日期、意向城市、岗位 | 有金额必须有周期 |
| employment_records | 学生、姓名快照、班级快照、公司、薪资、周期 | 日期、城市、岗位 | 快照由服务端必填入 |
| class_teacher_relations | 班级、老师、角色 | 无 | 三个全必填 |
| users | 账号、密码哈希、显示名、角色 | 所属班级、令牌 | 密码只存 bcrypt 哈希 |

## 7. 分页为什么重写（2026-10）

以前每个分页函数都重复写“查总数 + 算偏移 + 取一页”这 6 行，
文本条件有的用 `if x:` 有的用 `if x is not None:`，还容易被前端空字符串误伤。
现在统一收拢到 `backend/dao/common.py` 的两个小函数：

- `clean_text`：去首尾空格，空字符串按没填处理（返回 None）。
- `paginate`：先 `count()` 再 `offset().limit().all()`，返回 `(当页数据, 总数)`。

各 DAO 只写自己的筛选条件，调用前排好序再调 `paginate`。函数签名没变，
接口层一行都不用改。记住一句话：**筛选参数的 None 表示“不过滤”，
和字段是否必填没关系**——学号、姓名在库里永远有值。

## 8. 排班三铁律（2026-10 修订，各模块都要知道）

1. 一个老师同一时间只能负责一个**未结课**班级（班主任、授课老师都一样）。
2. 同一个班级里，班主任和授课老师不能是同一人。
3. 一个班级最多只能有一位在任班主任。
已结课班级的历史关系保留，但不占用老师；已结课班级不能新增排班。

## 10. 答辩通用话术（每人开场 30 秒）

> 我们做的是沃林学生管理系统基础版，我负责 XX 模块。
> 后端按 model、scheme、dao、api 四层分开：模型只定义表结构，
> Pydantic 做参数校验，DAO 只写增删改查，业务判断全在接口层用 if/else 写清楚。
> 全项目统一响应格式、统一错误码，所有删除都是逻辑删除，
> 普通查询默认过滤掉已删除数据。我的模块一共有 N 个接口，M 条测试用例，
> 覆盖正常流程、参数错误、业务冲突和逻辑删除。

预判提问 1：“为什么删除要用逻辑删除，不直接删？”
> 因为成绩、就业都是历史数据，删学生不能把历史一起弄丢。
> 逻辑删除只打标记，普通查询过滤掉，数据还在库里可查可审计。
> 而且编号全表唯一，物理删除后编号被复用，历史记录就串了。

预判提问 2：“404 和 409 怎么分？”
> 404 是“东西不在”：记录不存在、已删除、关联对象没了。
> 409 是“东西在但冲突”：编号重复、有学生还想删班级、老师已被占用。
> 我们的业务码就是状态码 × 100 + 1，前端一看就知道是哪类问题。
