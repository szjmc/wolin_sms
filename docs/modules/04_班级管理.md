# 04 · 班级管理（成员 4）

## 1. 一句话职责

管班级档案和“谁能删班级”。最重要的就是那条规矩：班里还有学生，
哪怕只剩一个，班级不准删——不然学生就没班可归，成了孤儿数据。

文件：`model/class_info.py`、`scheme/class_info.py`、`dao/class_dao.py`、
`api/class_api.py`，测试 `tests/test_classes.py`（26 条）。

## 2. 接口一览（5 个）

| 方法与路径 | 作用 |
|---|---|
| POST `/api/v1/classes` | 新增班级（预留预留表单可带班主任/任课老师 ID） |
| GET `/api/v1/classes` | 分页：班号/班名/状态 |
| GET `/api/v1/classes/{id}` | 详情 |
| PATCH `/api/v1/classes/{id}` | 只传要改的字段 |
| DELETE `/api/v1/classes/{id}` | 逻辑删除，学生挡路 |

前端补充接口（契约一致）：`GET /classes/{id}/overview` 返回
班级信息、总人数、性别人数、及格率、平均分、全部达标人数、已就业人数；
班级新建可一次带上 `head_teacher_id` 和 `teacher_ids`（序列化的老师 ID）。

## 3. 请求体逐字段

ClassCreate：必填 `class_no`（全表唯一，含已删）、`class_name`、`start_date`；
可选 `completion_date`（未结课可以空）、`class_status`（未开班/在读/已结课，
默认在读）。建班若带老师：`head_teacher_id`（正整数）
`teacher_ids`（正整数数组）；姓名不存，从 ID 关联读。
ClassUpdate：全部可选，班级编号永不许改；必填字段传 null 拦 422。

## 4. 每个接口的处理步骤

**新增（带排班时）**：① 班号查重含已删除（409）→
② 逐个检查班主任和任课老师：存在且未删（404）、在职且可授课（409）、
未被其他未结课班级占用（409）→
③ 班主任与任课老师不能同人（422）→
④ 班级和关系在一个事务里插入。单个老师冲突整批回滚，不建半成品。

**删除**：① 班级存在未删（404）→ ② 这班还有未删除学生吗？
有 → 409「该班级下仍有学生，不能删除」→
③ 还挂着有效排班关系 → 409 → ④ 打删除标记。成功 204。

## 4.5 班级详情里调整学生班级（2026-11 新增）

班级详情页的「班级学生」页签，每行都有**调整班级**按钮：
选目标班 → 确认 → `PATCH /students/{id}` 只传 `class_id`。
规则：转班只改学生的"当前班级"，成绩、就业历史快照全部保留；
班主任只能给自己班的学生转班，且目标班也必须在自己权限内（否则 403）。
转班后班级人数、及格率、性别分布立即刷新。

## 5. 业务规则和边界

- 状态流转：未开班 → 在读 → 已结课；已结课后换个方式处理历史，
  直接重开班要重新检查该班全体老师当前空闲状态。
- 结课日期早于开班日期：新增 422、修改后犯 400。
- 编号全表唯一，已删除班的班号不能复用——防止编号被历史快照反查时串味。
- 班级删除绝不物理删：成绩和就业快照就是靠班号（或班 id)延长的历史，
  物理删班级就没法对照了。

## 6. 测试清单（26 条重点）

正常：结课时间空建班、已结课记日期、Patch 只改提交字段。
异常：班号重复 409、空班号 422、结课早于开班 422/400、状态非法 422、
必填传 null 422、分页参数超范围 422。
删除：空班删后 404/列表消失/班号不复用；有学生时 409 且提示语准确；
有排班关系时 409。

## 7. 答辩话术

60 秒介绍：
> 我负责班级管理，5 个后端接口。卖点第一是删除守卫：
> 先查未删除学生人数，有学生返回 409 “该班级下仍有学生，不能删除”，
> 再看排班关系，防住孤儿数据；第二是新建班级可以一次把班主任和任课老师带好，
> 老师必须在职可授课且未被其他班占用，班主任和任课老师不能同人，
> 整个创建是一笔事务，任何一个不合格整体回滚。
> 测试 26 条，重点覆盖日期顺序、删除守卫和编号防重。

预判提问 4（出题人给的图里就有）：**“班级下有学生，能删除吗？会产生孤儿数据吗？”**
> 不能删除。我的 `delete_class` 一开场就查 `students` 表：
> `count_students_by_class(class_id) > 0` 就直接返回 409，
> 原话是“该班级下仍有学生，不能删除”。思路是跟“先拦截后删除”一致的：
> 宁可拒绝也绝不产生孤儿。等学生被逐个逻辑删除或转班处理完，
> 还要排班关系也解除，才允许把班级打上删除标记。
> 注意是逻辑删除，班级档案还在库里，历史就业快照按班号还能追溯。

预判提问 2：“为什么不物理删除，库不干净吗？”
> 不干净历史就查不到。学生、成绩、就业快照很多时候靠班号追溯。
> 逻辑标记普通查询全过滤掉，使用上跟删了没有区别，审计时又还在。

预判提问 3：“新班没指定结课日期会怎么样？”
> 合法，因为班级未结课就没日期，前端展示“未结课”。
> 结课后补录即可，但不能早于开班日期。
