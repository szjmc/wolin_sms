# 01 · 学生信息管理（成员 1）

## 1. 一句话职责

管学生建档、查档、改档、删档。核心就两件事：
年龄只存出生日期、动态计算；学生编号全局唯一、创建后不许改。

文件清单：`model/student.py`、`scheme/student.py`、`dao/student_dao.py`、
`api/student_api.py`，测试 `tests/test_students.py`（25 条）。

## 2. 接口一览（5 个）

| 方法与路径 | 作用 | 成功 |
|---|---|---|
| POST `/api/v1/students` | 新增学生 | 201 + StudentRead |
| GET `/api/v1/students` | 分页列表：学号/姓名/班级/性别/年龄 | 200 + PageData |
| GET `/api/v1/students/{id}` | 详情（含年龄） | 200 |
| PATCH `/api/v1/students/{id}` | 只传要改的字段 | 200 |
| DELETE `/api/v1/students/{id}` | 逻辑删除 | 204 无响应体 |

## 3. 请求体逐字段（StudentCreate）

| 字段 | 必填 | 规则 | 说明 |
|---|---|---|---|
| student_no | 是 | 1–30 字符 | 学号，全表唯一，建档后不改 |
| class_id | 是 | 大于 0 的整数 | 班级必须存在且未删除 |
| name | 是 | 1–50 字符 | 学生姓名 |
| birth_date | 是 | 不能晚于今天 | 年龄就靠它算 |
| gender | 是 | 男/女/其他 | 枚举，写死 |
| hometown / graduate_school / major / education / consultant_no | 否 | 长度限制 | 建档后可补 |
| training_enrollment_date / training_graduation_date | 否 | 结课不能早于入学 | 注意这是**培训机构**的时间，不是原学校的时间 |

StudentUpdate：字段一样但全可选；`class_id/name/birth_date/gender`
一旦传了就不能传 `null`（数据库必填）。

## 4. 每个接口的处理步骤

**新增**：① 班级存在吗（404）→ ② 学号重复吗，含已删除（409）→
③ 入库 → ④ 算年龄返回。Pydantic 先拦掉未来生日和倒挂的培训日期（422）。

**列表**：把 5 个筛选条件交给 DAO；`age_gt` 先换算成出生日期上限
（年龄 > N 等价于 `birth_date <= 今天往前推 N+1 年`），直接比日期走索引。
分页走 `dao/common.py` 的 `paginate`。

**详情**：查不到或已删除 → 404；查到就组装 `StudentRead`，年龄现场算。

**更新**：① 学生存在（404）→ ② 只取本次提交的字段
（`exclude_unset=True`，没传的字段绝不碰）→ ③ 换班先查新班存在 →
④ 用“改完的值”重算培训日期先后（400）→ ⑤ 保存。

**删除**：只给学生打标记。成绩、经历、就业记录一行不动全保留，
普通查询会自动把它们藏起来。

## 5. 响应体逐字段（StudentRead）

`id / student_no / class_id / name / birth_date / age / gender /
created_at / updated_at` 必有值，前端直接展示不用判空。
`hometown / graduate_school / major / education / consultant_no /
training_enrollment_date / training_graduation_date` 可能为空。
`age` 是整数（出生日期必填，所以年龄一定算得出来）。

## 6. DAO 函数（5 个，不写业务判断）

`get_student_by_id`（只查未删）、`get_student_by_no`（查全部，专供查重）、
`list_students`（5 条件 + 统一分页）、`list_students_by_ids`（统计用）、
`count_students_by_class`（删班前检查用）、`create/update/delete_student`。

## 7. 业务规则和边界

- 学号全表唯一：删掉的学生占着学号也不许复用，防止历史串号。
- 培训日期和原学校日期是两回事：`training_*` 是培训机构的，
  `graduate_school/major` 是原来的学历，前端标签不许写混。
- 客户端传 `age` 直接忽略，年龄永远服务端算。
- 2 月 29 日出生的学生做年龄换算时有闰年兜底（目标年没 2 月 29 日就用 28 日）。

## 8. 测试清单（25 条，挑重点记）

正常：新增成功、年龄 35 岁算对、边界生日（今天满 31、当天差一天 30）、
客户端 age 被忽略、PATCH 只改提交字段、可空字段传 null 清空。
异常：班级不存在 404、未来生日 422、培训日期倒挂 422（新增）/400（修改）、
非法性别 422、学号重复 409、必填传 null 422、必填缺失 422。
删除：删后详情 404、列表消失、学号仍不可复用。

## 9. 答辩话术

60 秒介绍：
> 我负责学生信息管理，5 个接口：增、分页查、详情、改、逻辑删除。
> 三个关键设计：第一，库里只存出生日期，年龄每次返回时现场算，
> 年龄筛选换算成出生日期比较，能走索引；第二，学号全表唯一，
> 连已删除的都占着，防止复用串号；第三，PATCH 用 exclude_unset，
> 只改用户提交的字段，改完再用最终值校验培训日期先后。
> 测试 25 条，重点覆盖年龄边界、日期倒挂和逻辑删除。

预判提问 1：“年龄为什么不存数据库？”
> 存了就得天天批量更新，还容易和生日对不上。只存生日、每次现算，
> 永远是对的。列表筛选也不逐行算年龄，而是换算成生日条件直接让数据库比。

预判提问 2：“PATCH 时 birthday 传 null 会怎样？”
> 会被 422 拦掉。PATCH 允许不传，但数据库必填的四个字段
> （班级、姓名、生日、性别）一旦传了就不能是 null，这是 check_not_null 保证的。

预判提问 3：“删学生会把成绩一起删吗？”
> 不会。只给学生打标记，成绩、经历、就业全保留。
> 但普通查询会同时检查“记录没删 + 学生没删”，所以前台看不到，
> 统计也不会把已删学生算进去。
