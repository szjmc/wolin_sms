# 管理员账号恢复：已有数据也能恢复登录

## 1. 解决什么问题

系统的「第一个账号自动成为管理员」只用于账号表真正为空时。学生档案存在并不决定初始化状态，但账号表已经有账号（包括历史删除账号）时，不应让匿名用户再次注册成管理员。

如果管理员用户名或密码已遗失，不需要重建数据库、删除 users、开放匿名管理员注册。通过有部署终端权限的维护人员恢复指定管理员即可。

**项目没有通用默认管理员密码。tests/conftest.py 的测试密码不是正式库登录凭据。**

## 2. 当前预览环境

当前平台预览未配置 `WOLIN_API_URL` 时，使用平台的 Next.js/Drizzle 数据源：

- 查看账号名和启用状态：`npx tsx scripts/reset-preview-admin.ts --list`
- 恢复现有管理员：`npx tsx scripts/reset-preview-admin.ts --username admin --generate`
- admin 不存在时显式创建：`npx tsx scripts/reset-preview-admin.ts --username admin --create-if-missing --generate`

`--generate` 只在执行成功时输出一次随机临时密码。自行设置密码时，从终端的 `WOLIN_ADMIN_PASSWORD` 环境变量提供，不要把密码提交到 Git。

脚本通过 `@/db` 的 Drizzle 客户端读写，只修改指定管理员的密码哈希、启用/删除状态和令牌。不会执行 bootstrap，不碰任何业务表。

配置了 `WOLIN_API_URL` 时，脚本会拒绝操作预览库，提示在真正的 FastAPI 部署上运行下面的 Python 工具，防止重置错数据库。

## 3. Python + MySQL 正式部署

安装 `backend/requirements.txt` 的依赖，并配置 `backend/.env` 中的 `WOLIN_DB_URL=mysql+pymysql://...`。本工具不接受其他数据库，也不会猜测地址。

在项目根目录执行：

1. 查找现有管理员：`python backend/reset_admin.py --list`
2. 恢复指定账号：`python backend/reset_admin.py --username admin`
3. 按提示输入新密码两次（getpass 隐藏输入）。
4. 需要创建新管理员时，使用 `python backend/reset_admin.py --username admin --create-if-missing --generate`。
5. 回到网站根路径登录，进入右上角「个人信息」修改临时密码。

脚本只使用 SQLAlchemy，不导入 `main.py`，不自动建表、更不清库。已有用户名属于非管理员时会拒绝重置，避免误把普通用户提权。

## 4. 密码和令牌

- 新建、改密、重置统一使用 bcrypt 加随机盐，最多 72 个 UTF-8 字节；密码空格保留原样。
- 旧版预览的 scrypt 哈希仍可验证；只有登录成功后才升级为 bcrypt。
- 重置时清空指定账号的旧令牌，并恢复启用状态。
- 损坏哈希按登录失败处理，不返回服务端 500。
- 登录页只有在 `/auth/me` 验证成功后才跳工作台，不能仅凭 localStorage 有个字符串就跳转。
- 401 会清除同一个旧令牌和缓存用户信息，防止根路径和工作台来回跳转。
- 后端服务断线显示重试提示，不把 500/503 当成正常退出。
- 对接 Python 时，Next.js 代理必须转发 Authorization 头。

## 5. 安全边界

没有公开的「忘记密码免验证重置 admin」接口；没有固定万能密码；没有启动时覆盖管理员密码的种子逻辑。恢复命令要求能进入部署终端且具有数据库访问权限。

临时密码只发给系统所有者，不显示在登录页面、角色列表、接口响应或仓库文件中。

## 6. 验收

- 已有业务数据与管理员时，创建/恢复指定管理员后可以登录。
- 重置前后业务表记录数相同。
- 旧密码与旧令牌失效，新密码可正常登录并访问个人信息。
- 损坏/过期令牌自动清理，浏览器停留在登录页而不是无限跳转。
- 普通账号不能通过此流程在网页中获得管理员权限。
- 访客可自助注册只读账号；管理角色账号需由管理员创建。
- 已初始化的注册页解释正确处理方式，不让用户反复提交必然失败的首次注册。
