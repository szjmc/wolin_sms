## 二、开发决策记录（文档中"待团队确认"事项的落地方案）

| # | 待定问题 | 本次实现采用的决策 |
|---|---|---|
| 1 | 老师 `phone` 与 `contact_info` 重复 | 采用文档建议：`phone` 只存电话号码，`contact_info` 存微信、邮箱等补充方式 |
| 2 | 就业日期精度 | 保持 `DATE`：`employment_open_date`、`offer_date`；若要精确到时分秒，需同步修改 MySQL 列与 Pydantic 类型 |
| 3 | 班级状态取值 | `未开班` / `在读` / `已结课`，默认 `在读` |
| 4 | 老师状态 | V1.1 需求要求维护"状态"，V1.3 未列出；新增 `teacher_status`：`在职` / `离职`，默认 `在职` |
| 5 | 学生出生日期是否必填 | 按 V1.3 设为必填（`age` 始终可计算）；`calculate_age()` 仍兼容空值 |
| 6 | 业务编号唯一范围 | `student_no` / `class_no` / `teacher_no` 全表唯一（含已删除记录），已删除记录的编号不可复用 |
| 7 | 成绩唯一与重录 | 不建普通 `UNIQUE(student_id, exam_no)`；接口层校验"同一学生同一序次只有一条未删除成绩"，逻辑删除后允许重录 |
| 8 | 已删除学生的子数据 | 成绩、过往经历、就业记录保留在库中；普通查询与统计中，所属学生已删除的记录一律不可见（详情返回 404） |
| 9 | 就业记录的班级口径 | 统一按 `class_no_snapshot`（班级编号快照）：班级筛选、班级就业记录、就业时长、班级平均就业时长 |
| 10 | 薪资范围筛选 | `min_salary` / `max_salary` 按原始金额；新增 `min_annualized_salary` / `max_annualized_salary` 按年薪等价值 |
| 11 | 删除接口响应 | 全项目统一返回 HTTP 204，无响应体 |
| 12 | 班级老师关系 | 2026-10 修订：一位老师同一时间只负责一个未结课班级；班主任与授课老师不能是同一人；一班最多一位班主任。PUT 幂等；解除后再建立会新增一条记录（保留历史） |
| 13 | 薪资排名并列 | 年薪等价值相同时按记录 ID 升序，名次顺延（1、2、3…） |
| 14 | 错误码映射 | 业务码 = HTTP 状态码 × 100 + 1：40001 / 40401 / 40901 / 42201 / 50001 |
| 15 | 关联对象不存在 | 例如新增学生时 `class_id` 无效、新增成绩时学生已删除，统一返回 404 |
| 16 | 筛选匹配方式 | 编号类字段精确匹配；姓名、名称、公司、城市、岗位、专长等文本字段模糊匹配 |
| 17 | 创建时与修改时的日期校验 | 新增时由 Pydantic 校验（422）；PATCH 时用"修改后的值"在接口层校验（400） |
